### Remaining Pre-Production Launch Gates (Honest Status)

Before accepting public MMO traffic or real-money transactions, the following items still require completion outside local single-node verification:

1. **Multi-Instance Realm Persistence**: Migrate single-node JSON realm state (`data/online_realm_state.json`) to PostgreSQL (`src/db/`) + Redis pub/sub for horizontal scaling across stateless containers.
2. **Server-Authoritative Economy & Billing**: Move all currency/resource mutations to server-side transactions and integrate verified payment webhooks before enabling paid VIP tiers.
3. **External Load, Soak & Security Testing**: Execute multi-hour distributed WebSocket soak tests (`k6`/Artillery) behind a real reverse proxy and conduct an independent security audit.
4. **Release & Governance**: Push the first signed `v1.5.0` tag to trigger `.github/workflows/release.yml`, enable GitHub branch protection rules on `main`, and have legal counsel review `EULA.md` / `LEGAL.md`.

## 4. Badge Style & Maintenance Conventions

- **Live CI Badges Only**: Never replace live GitHub Actions workflow badges (`actions/workflows/<file>/badge.svg`) with static green Shields.io strings.
- **Style Standard**: Append `?style=flat-square` to static Shields.io metadata badges for visual consistency across `README.md`, `badges.md`, and release documentation.
- **Sync Checklist**:
  1. When bumping `version` in [`package.json`](./package.json), update the `Source_Version` badge here and in [`README.md`](./README.md).
  2. When adding or modifying automated test suites, run `npm test` and keep the `Automated_Tests` count synchronized with the exact passing count (`229` tests across `41` test files).
  3. After publishing the first `v*.*.*` Git tag via [`.github/workflows/release.yml`](./.github/workflows/release.yml), replace the `Source_Version` static badge with the live GitHub Release badge (`https://img.shields.io/github/v/release/Gitinclo/Voxel-Realms-RPG-Open-World-MMORPG-Castle-Warfare?style=flat-square`).
